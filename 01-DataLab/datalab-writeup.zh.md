# 正文翻译

## 1. 引言

本次作业的目的是让你更熟悉整数和浮点数的**位级表示**。你将通过解一串编程"谜题"来做到这一点。其中很多谜题相当"人工造作"，但在解决它们的过程中，你会对"位"思考得多得多。

## 2. 安排（Logistics）

这是**个人独立项目**。所有提交均为电子提交。勘误与修正会发布在课程网页上。

## 3. 发题说明（Handout Instructions）

> 按学校填写：此处插入一段，说明老师如何把 `datalab-handout.tar` 发给你们。

先把 `datalab-handout.tar` 复制到你计划工作的 Linux 机器上的一个（受保护的）目录中，然后执行命令：

```
unix> tar xvf datalab-handout.tar
```

这会把若干文件解压到该目录。**你唯一需要修改并提交的文件是 `bits.c`。**

`bits.c` 中包含全部 **13 个编程谜题**的函数骨架。你的任务是：对整数谜题，只用**直线代码**（straightline code，即无循环、无条件）和有限数量的 C 算术与逻辑操作符，把每个函数骨架补全。具体地，你只允许使用下面**8 个操作符**：

```
 ! ~ & ^ | + << >>
```

其中少数函数还会进一步限制这个清单。另外，**不允许使用超过 8 位长的常量**。详细的规则和期望的编码风格，请看 `bits.c` 里的注释。

## 4. 谜题（The Puzzles）

本节描述你要在 `bits.c` 中解决的谜题。

表 1 按难度从易到难大致列出这些谜题。"Rating" 字段是谜题的难度评分（该题的分值），"Max ops" 字段是允许你实现该函数所用的**最大操作符数**。关于各函数的期望行为，详见 `bits.c` 注释；你也可以参考 `tests.c` 里的测试函数——它们被用作表达你函数"正确行为"的参考函数，不过它们本身并不满足编码规则。

### 表 1：Data Lab 谜题清单

| 函数名 | 功能描述 | 分值(Rating) | 最多操作符(Max ops) |
|---|---|---|---|
| `bitXor(x,y)` | 只用 `&` 和 `~` 实现 x ^ y [注1] | 1 | 14 |
| `tmin()` | 最小的补码整数 | 1 | 4 |
| `isTmax(x)` | 仅当 x 是最大的补码整数时为真 | 1 | 10 |
| `allOddBits(x)` | 仅当 x 的所有奇数位都为 1 时为真 | 2 | 12 |
| `negate(x)` | 不用 `-` 操作符返回 -x | 2 | 5 |
| `isAsciiDigit(x)` | 若 0x30 ≤ x ≤ 0x39 为真 | 3 | 15 |
| `conditional(x,y,z)` | 等价于 x ? y : z | 3 | 16 |
| `isLessOrEqual(x,y)` | x ≤ y 为真，否则为假 | 3 | 24 |
| `logicalNeg(x)` | 不用 `!` 操作符计算 !x | 4 | 12 |
| `howManyBits(x)` | 用补码表示 x 所需的最少位数 | 4 | 90 |
| `floatScale2(uf)` | 返回浮点参数 f 的 2\*f 的位级等价结果 | 4 | 30 |
| `floatFloat2Int(uf)` | 返回浮点参数 f 的 (int)f 的位级等价结果 | 4 | 30 |
| `floatPower2(x)` | 返回整数 x 的 2.0^x 的位级等价结果 | 4 | 30 |

[注1] 原文表格写作 "x || y using only & and ~"，这是 CMU 原文档的一处**笔误**；按 `bits.c` 里骨架注释，本题正确要求是用 `&` 和 `~` 实现 **x ^ y**（异或）。

> 说明：对浮点谜题而言，值 **f** 是位表示与无符号整数 **uf** 相同的那个浮点数。

对浮点谜题，你要实现一些常见的**单精度浮点运算**。这类谜题**允许**使用标准控制结构（条件、循环），也允许同时使用 `int` 和 `unsigned` 数据类型，包括任意无符号/整型常量。但**不允许**使用任何 union、struct 或数组。最重要的是，**不允许**使用任何浮点数据类型、浮点操作或浮点常量。取而代之，任何浮点操作数都会以 `unsigned` 类型传入函数，任何返回的浮点值也以 `unsigned` 类型返回。你的代码应当通过位操作来实现指定的浮点运算。

附带的 `fshow` 程序能帮你理解浮点数的结构。要编译 `fshow`，进入 handout 目录后输入：

```
unix> make
```

你可以用 `fshow` 查看任意位模式作为浮点数时代表什么：

```
unix> ./fshow 2080374784

Floating point value 2.658455992e+36
Bit Representation 0x7c000000, sign = 0, exponent = f8, fraction = 000000
Normalized.  1.0000000000 X 2^(121)
```

（中文：浮点值 = 2.658455992e+36；位表示 = 0x7c000000，符号位 = 0，指数 = f8，尾数 = 000000；规格化数，1.0000000000 × 2^121）

你也可以给 `fshow` 传十六进制或浮点数值，它会解析出它们的位结构。

## 5. 评分（Evaluation）

你的总分按**满分 67 分**计算，分布如下：

- **36 分** 正确性（Correctness）
- **26 分** 性能（Performance）
- **5 分** 风格（Style）

**正确性分。** 你要解的谜题被赋予 1~4 的难度评分，使它们的加权和正好为 36。我们将用下一节描述的 `btest` 程序来评测你的函数。**一个谜题若通过 btest 的全部测试，即得满分；否则 0 分。**

**性能分。** 本阶段课程主要关心的是你能得出正确答案。但我们想培养你"尽量写得简短简单"的意识。而且，有些谜题可以暴力解决，但我们希望你更巧妙。因此，我们对每个函数规定了允许使用的**最大操作符数**。这个上限非常宽松，只为抓住**严重低效**的解法。**每个正确且满足操作符上限的函数得 2 分。**

**风格分。** 最后，我们预留 5 分，用于对你解法的风格和注释做**主观评价**。你的解法应尽可能干净、直白；注释应提供有效信息，但不需冗长。

### 自我评分工具（Autograding your work）

handout 目录里附带了一些自动评分工具——`btest`、`dlc` 和 `driver.pl`——帮助你检查工作的正确性。

- **btest**：该程序检查 `bits.c` 中各函数的功能正确性。构建并使用它，输入下面两条命令：

  ```
  unix> make
  unix> ./btest
  ```

  注意：**每次修改 `bits.c` 后都必须重新构建 btest**。建议你一次只解一个函数、边做边测。用 `-f` 选项可让 btest 只测试单个函数：

  ```
  unix> ./btest -f bitXor
  ```

  你还可以用 `-1`、`-2`、`-3` 选项传入指定参数：

  ```
  unix> ./btest -f bitXor -1 4 -2 5
  ```

  运行 btest 的完整文档见 `README` 文件。

- **dlc**：这是来自 MIT CILK 小组的一个 ANSI C 编译器的修改版，用于检查每个谜题是否遵守编码规则。典型用法：

  ```
  unix> ./dlc bits.c
  ```

  除非检测到问题（如非法操作符、操作符过多、整数谜题出现非直线代码），否则程序静默无输出。加 `-e` 开关：

  ```
  unix> ./dlc -e bits.c
  ```

  会让 dlc 打印每个函数使用的操作符数量。输入 `./dlc -help` 可查看全部命令行选项。

- **driver.pl**：这是利用 `btest` 和 `dlc` 计算你解法的正确性与性能分的驱动程序。它不需要参数：

  ```
  unix> ./driver.pl
  ```

  老师将用 `driver.pl` 评测你的解法。

## 7. 建议（Advice）

- **不要**在 `bits.c` 里 `#include <stdio.h>`，因为它会干扰 dlc，产生一些费解的错误信息。不包含该头文件，你仍然可以在 `bits.c` 里用 `printf` 调试（gcc 会打印警告，可忽略）。
- `dlc` 强制比 C++ 或 gcc 更严格的 C 声明形式。特别是，**任何声明都必须出现在某个代码块（花括号内）的开头，并且位于任何非声明语句之前**。例如，下面这段代码它就会报错：

  ```c
  int foo(int x)
  {
     int a = x;
     a *= 3;     /* 非声明语句 */
     int b = a; /* 错误：此处不允许声明 */
  }
  ```
